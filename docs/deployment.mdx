Approval and deployment are separate stages. Final approval accepts a service
request and starts an asynchronous operation against the target infrastructure:

- Registration creates the remote service configuration;
- Reconfiguration updates it; and
- Deregistration removes it.

#### Deployment process overview

![Deployment process overview](/img/screenshots/deployment_process.png)

While deployment is in progress, the service is shown with a waiting deployment
state. You can view it, but further service requests are normally blocked until
deployment completes. A reconfiguration that changes only Registry-managed
information may complete immediately because no remote update is required.

## Deployment failures

A failed deployment does not mean the request is waiting for review. The
request has already been approved, but the target infrastructure could not
apply it. The service entry displays a malfunction or error indicator.

#### Service with a deployment error

![Service with a deployment error](/img/screenshots/service_list_error.png)

Open the service to inspect the reported error. If your permissions include
deployment recovery, the error panel offers the actions configured for that
failure. Otherwise, provide the service name, target environment, and displayed
error to the tenant's support team. Do not create a duplicate registration to
work around the failure.
